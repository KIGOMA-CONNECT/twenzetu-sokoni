# AfriMarket Enterprise Constitution

> "Hii ndiyo document muhimu kuliko zote katika project. Sio technical document. Sio user manual. Sio README. Ni Constitution."

The Constitution is the founding law of AfriMarket. It states **who we are**, **where we are going**, **how we build**, and **how we decide**. Every technical document, repository, platform, and decision must be consistent with it. When in doubt, the Constitution wins.

## How to read this Constitution

- Chapters 1–4 define **who we are** (identity, vision, mission, values).
- Chapters 5–7 define **how we build** (engineering, architecture, product).
- Chapters 8–9 define **how we govern and decide** (governance, decision framework).
- Chapter 10 defines **where we are going** (the future, platform roadmap, maturity).

This document is designed to grow to hundreds of pages over time as the platform matures, while remaining version-controlled and traceable.

## Amendment process

The Constitution evolves, but only deliberately.

1. **Proposal.** Any amendment is proposed as a pull request against this folder, with a clear statement of the problem the amendment solves.
2. **Review.** Amendments are reviewed by the maintainers/council (see [Chapter 8](../constitution/08-governance-principles.md)).
3. **Ratification.** An amendment is adopted when it is consistent with the Vision and Core Values, and is approved by the governing body.
4. **Record.** Every amendment must:
   - bump the version in this document,
   - link the pull request that ratified it,
   - not silently rewrite history — amendments are additive and traceable.

### Versioning convention

- `vX.Y` — X = chapter-level revision, Y = editorial revision.
- Every change is recorded in the **Amendment Log** at the bottom of this document.
